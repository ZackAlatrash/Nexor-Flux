# Roadmap — July 2026

Companion to [the full code review](../reviews/2026-07-full-project-code-review.md). That document says what's wrong; this one says what to do and in what order — fixes, performance work, feature investments, and process changes. Effort tags: **S** ≤ half a day, **M** 1–3 days, **L** a week+.

---

## 1. Where the app stands

Recomp Tracker is a feature-complete personal body-recomposition app with an unusually strong deterministic core:

| Area | State |
|---|---|
| **Nutrition** | Food log with slots, planned (future) meals, per-day plan-version targets, NEVO + Open Food Facts + Samsung import, barcode scanner, recipes, meal suggestions, streaks |
| **Body & recovery** | Daily check-ins (weight/waist/sleep/scores/steps), Health Connect sync with provenance-aware steps reconciliation, calendar-accurate sparklines, history/edit |
| **Training** | Routine planner, live session tracking (survives process death), PR detection, exercise library (870+ seeded), muscle body-map heat, readiness verdicts, deload logic |
| **Adjustment loop** | Weekly verdict engine (trend + adherence + recovery → hold/±kcal), weekly review with AI briefing, plan history that never re-judges logged days |
| **Weekly Rebalance** | Fully merged: surplus-triggered offer → effective-target overlay (never mutates base plan), dual liquid-glass dials, exhaustively tested engine |
| **AI (cloud-only)** | Coach chat with 19 tools + write confirmation, insight cards, weekly briefing prose, signal phrasing, recipe namer, cited knowledge base (77 chunks), proactive signal engine (18 detectors + selector + rate-limited push) |
| **Platform** | Design system (tokens + glass components + real liquid-glass nav), onboarding, backup/restore, usage telemetry, Firebase distribution |

Quality picture: 1301 unit tests (1300 green; the one failure is the live-network harness being rate-limited), excellent domain coverage, genuinely good Compose craft in the hot spots — but **three P0 data-loss/crash bugs, 23 P1s, no CI test gate, and an untested backup/restore path**. The biggest risks are concentrated in a few seams (backup, time handling, read-modify-write races), not spread evenly.

In-flight branches to reconcile: `fix/cloud-coach-tool-calling` (the underlying bug is already fixed on develop — verify and close), `perf/liquid-glass-optimization` (lite variants already on develop; baseline-profile generation still pending), `perf/active-session-scroll` (overlaps §4.2 — land or fold), `redesign/ai-coaching` (planning only), `feat/pr-banner-muscle-usage`, `feat/dashboard-nav`, streak-tracking branches.

## 2. Fix first — data safety (this week)

These four make the difference between "a user can lose data" and not. All are small.

1. **Backup v2** — add the 7 training tables + custom exercises to `BackupPayload` (nullable defaults keep old backups importable); fix the slot-id remap (~5 lines, mirror the recipe path); gate import on `payload.version`; move prefs/rebalance restore inside the failure boundary. **(M)**
2. **Backup round-trip test** — real in-memory Room: export → `clearAllTables` → import → assert every table and slot links. `BackupRepositoryResetTest` already has the fixture shape. This single test would have caught both P0s. **(S)**
3. **Deep-link crash** — gate the navigate effect on `onboardingComplete == true` + graph readiness. **(S)**
4. **Keystore restore crash-loop** — `dataExtractionRules` excluding `secure_ai_prefs` + catch-and-recreate on decrypt failure in `SecureKeyStore`. **(S)**

And one process change that protects everything after it:

5. **CI test gate** — `pr.yml` on PRs + pushes to develop: `testDebugUnitTest` + `lint`, Gradle cache, wrapper validation, Firebase action pinned to a SHA. Move the live-network harness behind an explicit Gradle property so the suite is deterministic. **(S–M)**

## 4. Performance program

Ordered by measured-impact-per-effort. The app is CPU-healthy at today's data sizes; these keep it healthy at year-two data sizes and fix the two real interaction hotspots.

1. **`stateIn(WhileSubscribed(5s))` sweep** across Dashboard/FoodLog/Today/Progress/CoachToday/Rebalance ViewModels (StreakViewModel is the in-repo reference). Stops every Room write from recomputing invisible screens. **(M)**
2. **Live-session input path**: debounced or per-column set writes (also a P1 fix), stable callback holders so `ExerciseCard`s skip; `distinctUntilChanged`/windowed completed-sessions query so typing a rep doesn't re-run the Train-home stats over full history. **(M)**
3. **Windowed queries** for the unbounded reads: streaks, coach context, Progress meals, coach tool executor (`observeBetween`/`getCompletedSessionsSince` already exist). **(M)**
4. **Baseline profile**: run the already-built generator once on a device, commit `baseline-prof.txt`; then add a real `StartupBenchmark` to the macrobenchmark module. Consider occasionally distributing the `benchmark` build so testers feel R8+AOT performance. **(S–M)**
5. **Startup**: defer `SecureKeyStore` prefs to first use (async `hasKey` warm-up); fix or delete the vestigial `dbReady` gate; warm `MuscleArt` off-main. **(S–M)**
6. **Small wins**: horizontal-only chart scrub gestures; scrub state read in leaf texts; `usage_events` index + 90-day retention; food-library search filtering off-main with debounce; backup encode/decode off-main; body-history off-main + keyed items; transaction-batch the HC steps backfill. **(each S)**
7. **Build**: enable configuration + build caches locally and Gradle cache in CI; delete the two unused orb PNGs (~1.7 MB in every APK). **(S)**

## 5. Feature opportunities

Ranked within each area by user value; all grounded in what the code already supports.

### Training
- **Rest timer** — the one obviously missing feature of the live session. A per-set countdown starting on ✓, wall-clock deadline (`restEndsAt`) so it survives backgrounding, rendered with the same leaf-collection pattern as the elapsed timer (the architecture is already proven in-repo). **(M)**
- **Progressive overload suggestions** — `PrCalloutFormatter` already *promises* "it'll raise next week's target"; make it true with a one-tap "+2.5 kg next time" that patches the routine's planned set. All the math exists in `WorkoutProgressAnalyzer`/`ExerciseStatsCalculator`. **(M)**
- **Show planner targets in the live session** — target reps/kg are currently ignored beyond set count; render them as the PREV-style hint for first-time sessions. **(S)**
- Undo snackbar for destructive session edits; expose or purge ABANDONED sessions (dialog says "permanently deletes" — make it true); per-row identity for duplicate exercises (supersets/drop sets). **(S–M)**

### Coach & AI
- **Persist chat history** (small table or DataStore with the house pure-codec pattern) so process death and context resets stop wiping the conversation — the confirmation flow already makes replays safe. **(M)**
- **Persist the last Ready insight per kind** so the dashboard isn't blank after process death. **(S)**
- **Tool-calling hardening** (the lesson of the "Done." incident, as belt-and-braces): send `tool_choice: "auto"` (and `"required"` on the nudge retry); rescue content-embedded tool calls (reasoning-only models often *print* the call they never emit); a config-time probe on settings save that warns when a model can't emit `tool_calls`; make the deprecated-model remap a set. **(M)**
- **Error taxonomy + retry**: sealed cloud errors (Unauthorized / RateLimited / ServerError / Network) with distinct user messages, one jittered retry for read-only completions (insights/briefing/phrasing) — free-route 429s currently kill whole generations. **(M)**
- **Stop button** for in-flight coach turns (worst case today is minutes of `Thinking`); context-window management via rolling summary once `requestMessages` passes a budget. **(M)**
- **Stable knowledge citations** — inject `[kb:<chunk-id>]` instead of positional `[1]` so citations survive across turns and can become tappable sources in the UI. **(S–M)**
- Product decision to make explicit: should weekly-review adherence judge days against rebalance-**effective** targets (the overlay exists; today it judges base — a nailed −200 kcal rebalance week reads ~90% instead of ~100%). **(decision + S)**

### Food & nutrition
- Backup UX: import **preview** ("this file contains X logs, Y meals, Z routines — replace current data?") before the wipe; export counts; temp-file-then-rename writes. **(M)**
- Tappable `StalePlannedHint` jumping to the earliest unconfirmed day; disable day-nav at the ±30-day clamp; toast coalescing for confirm-all. **(S)**
- Fold the legacy `ui/foods` screen into the Food Library and delete it. **(M)**
- Camera-denied fallback that opens app settings. **(S)**

### Platform & polish
- **Design-token completion**: mode-aware `success`/`warning`/`overTarget` tokens (retires ~16 hex literals and fixes light-theme contrast), then the `AppType` sweep through `ui/component` (~40 hardcoded sizes), `ScreenScaffold` header slot (deletes 6 bespoke scaffolds), one shared menu-row, `GlassSegmentedToggle` in TrainHome, glass `OptionSheet`s in Onboarding/Profile. **(M–L total, mechanical)**
- **Dead-code deletion** (~900 lines incl. `LiquidSlider`/`LiquidToggle`): shrinks the API surface so the "one family" rules have no wrong options. **(S)**
- **Accessibility pass**: `minimumInteractiveComponentSize` on the small controls, checkbox semantics on the set-grid ✓, real `enabled=false` on glass buttons, icons instead of glyph affordances, content descriptions on charts/body map. **(M)**
- Gate the Developer menu row on `BuildConfig.DEBUG`; make "Reset all" actually reset profile/coach-memory/keys (or soften the copy). **(S)**
- Avatar: copy picked photos into `filesDir` instead of persisting picker URIs. **(S)**

## 6. Testing & infrastructure strategy

The suite is large but has a systematic blind spot: **only one test touches real Room**, so FK enforcement, REPLACE semantics, AUTOINCREMENT, and transactions are invisible — exactly where the P0/P1 data bugs live.

1. Backup round-trip against real Room (§2). **(S)**
2. `exportSchema = true`, commit `app/schemas/`, `MigrationTestHelper` chain test 1→15 — near-zero cost now, invaluable before schema v16. **(S–M)**
3. Real-Room tests for the FK-sensitive paths: library re-seed with referenced exercises, duplicate custom names, `startSession` (entirely untested today), set renumbering. **(M)**
4. Concurrency interleaving tests with gated fakes: digest double-run, HC sync vs check-in save, insight regeneration races. **(M)**
5. Fill the pure-logic gaps: trend calculator edge cases (zero e1RM, same-day points, recovery boundaries — 5 tests today for the highest-blast-radius calculator), adjustment-engine fallthrough branches, detectors fed through `TrainingDerivations` (would have caught the deload inversion), sparse-data trend points, `dotStateFor`, `toDeepLinkRoute`. **(M)**
6. A weekly `assembleRelease` CI job so R8 stays honest; prune the blanket proguard keeps. **(S)**
7. TodayViewModel and TrainViewModel test classes (both currently have zero). **(M)**
