Important Technical Decisions

  • Used Kotlin and Compose Material 3 because the plan specified a native Android MVP with a clean, maintainable UI layer.
  • Used Room for logs and saved items, and DataStore for plan preferences, because the plan requires reliable local persistence without accounts or a backend.
  • Kept the adjustment engine as pure Kotlin domain code so it is deterministic, testable, and independent of UI state.
  • Used a manual AppContainer instead of adding a DI framework, keeping the MVP simple while preserving separation of concerns.
  • Used Vico for charts instead of hand-drawn graph logic.
  • Excluded Gemma from calorie decisions; it is represented only as a future local insight boundary, matching the guardrail requirement.
  • Created local JDK 17 and Android SDK tooling inside the workspace because the machine did not initially have a working Android build environment.

Known Limitations

  • The MVP has a version 1 Room schema. Future schema changes should add explicit migrations before release.
  • Manual device validation was performed on an API 36 emulator, not a physical phone.
  • Gemma is not active in the MVP. That is intentional: the plan requires deterministic rule-based calorie decisions first.
  • Backup import accepts the local JSON shape generated by this app; broader schema-compatibility handling should be added if the format evolves.

Recommended Next Steps
