Local-first Android MVP plan

Recomp Tracker: Android App Implementation Plan

A simple private Android app for tracking calories, macros, weight, waist, training, recovery, charts, averages, and evidence-based calorie adjustments. No backend, no accounts, no onboarding, no hosting.

Executive Decision

Native AndroidKotlin, Jetpack Compose, Material 3, single-activity architecture.
Fully offlineRoom database as local source of truth; DataStore for preferences.
Rule engine firstDeterministic adjustment logic, not AI guessing.
Gemma laterOptional on-device insight layer after the MVP works.
Build the app as a personal control panel, not a consumer fitness product. The MVP should open directly to today’s logging screen, make daily input fast, calculate weekly trends automatically, and tell you whether to hold calories, add calories, reduce calories, or wait for more data.

Non-Negotiable Scope

Included in MVPExcluded from MVP
Manual calories/macros, bodyweight, waist, steps, sleep, hunger, soreness, energy, and training-day logging. User accounts, cloud sync, social features, subscriptions, public profiles, or multi-user support.
7-day, 14-day, and 28-day averages/trends. Barcode scanning, food-photo recognition, online food database, or restaurant integrations.
Rule-based calorie adjustment engine. AI making final calorie decisions.
Charts for weight, waist, calories, macros, adherence, and performance. Full workout programming platform.
Saved meals and quick copy-from-yesterday logging. Onboarding, coaching marketplace, or generic content library.
Local export/import for backup. Hosted database, web dashboard, or online account recovery.

Recommended Android Stack

AreaChoiceWhy
Language Kotlin Default modern Android language, concise, strong coroutine/Flow support, good for agent-generated code.
UI Jetpack Compose + Material 3 Fast to build, less XML, easy component reuse, official Android direction.
Architecture Single Activity + Compose Navigation + ViewModels Matches Android guidance: UI driven from state, ViewModels hold screen state, data stays outside the Activity.
Local database Room Best fit for structured offline logs, queries, migrations, and testability.
Preferences DataStore Preferences Stores current calorie target, macro targets, units, review cadence, and app settings.
Async/reactive data Kotlin Coroutines + Flow Room can expose streams; UI updates automatically when logs change.
Charts Vico Compose-compatible charting library suitable for line/bar trend charts without embedding old View charts.
Dependency setup Manual AppContainer first For a personal app, manual dependency wiring is simpler than Hilt. If the project grows, Hilt can be introduced later.
Export/import kotlinx.serialization + Android Storage Access Framework Simple local JSON backup/restore without hosting anything.
AI phase Gemma via Google AI Edge / MediaPipe LLM Inference Only after MVP. Use it for summaries and explanations, not core decisions.
Testing JUnit, kotlinx-coroutines-test, Room in-memory tests, Compose UI tests The adjustment engine and trend math need reliable tests because bad logic means bad nutrition decisions.

Use Android Studio’s latest stable Kotlin/Compose template and keep dependency versions in a Gradle version catalog. At implementation time, verify current stable versions rather than freezing versions in this planning document.

Core Data Model

Adjustment Engine

The adjustment engine should be plain Kotlin and independent from Android UI classes. It receives trend summaries and returns a verdict.

ConditionVerdictRecommendation
Fewer than 14 days of usable data, or adherence below 85%. Wait No calorie change. Improve logging consistency.
First 7-10 days after raising calories from the cut. Ignore scale jump No calorie change unless waist jumps sharply and continues rising.
Weight trend within +/-0.20 kg/week, waist stable/down, performance stable/up. Hold Keep current calories and macros.
Weight falling faster than 0.20 kg/week and performance or recovery is poor. Increase Add 100-150 kcal/day, mostly carbs.
Weight rising faster than 0.20 kg/week for 2 weeks and waist is rising. Reduce Remove 100 kcal/day, mostly carbs or fats depending on adherence.
Weight up, waist stable, performance up. Hold Likely glycogen, water, or lean-mass trend. Do not cut. 
data class AdjustmentInput(
    val daysLogged: Int,
    val adherencePercent: Double,
    val weeksSincePhaseStart: Int,
    val weightTrendKgPerWeek: Double,
    val waistTrendCmPerWeek: Double,
    val performanceTrend: PerformanceTrend,
    val recoveryTrend: RecoveryTrend
)

enum class AdjustmentVerdict {
    WAIT_FOR_DATA,
    HOLD,
    INCREASE_CALORIES,
    REDUCE_CALORIES
}

Implementation Phases

PhaseBuildAcceptance Checks
0. Project foundation Create Android Studio project, Gradle version catalog, Compose app shell, Material 3 theme, AGENTS.md and docs. App launches on Android emulator/device. README commands work. Agent docs exist.
1. Local database Room database, entities, DAOs, repositories, DataStore preferences. Unit/instrumented tests can insert logs, meals, foods, and query day totals.
2. Today logging Today screen with macro fields, body metrics, recovery scores, training toggle, saved meals, copy yesterday. Entering data updates day totals instantly and persists after app restart.
3. Trend math Moving averages, weekly trends, adherence calculation, performance trend calculation. Pure unit tests cover missing data, first-week scale jump, low adherence, and normal maintenance trend.
4. Dashboard verdict Adjustment engine and dashboard cards. Dashboard returns hold/increase/reduce/wait with readable reasons and no AI dependency.
5. Charts Progress screen using Vico for weight, waist, calories, macros, adherence, and selected lift charts. Charts handle empty data, partial data, and 7/14/28-day filters.
6. Plan and settings Edit calorie/macro targets, thresholds, backup/export/import, reset data. Target edits affect dashboard immediately. Export/import round trip preserves data.
7. Optional Gemma insights On-device summary generator using Google AI Edge / MediaPipe LLM Inference. AI can summarize a week, but cannot change calorie targets or override the rule engine.

Detailed Build Notes

Keep It Easy to Use

  • App opens to Today.
  • All common fields visible without hunting through menus.
  • Large numeric inputs with previous value shortcuts.
  • One tap to copy yesterday’s meals.
  • Saved meals should be quicker than manual entry.
  • Dashboard verdict must be short: Hold, Increase, Reduce, or Wait.

Keep It Easy to Code

  • Use one app module for MVP.
  • Keep domain logic pure Kotlin.
  • Use manual dependency wiring first.
  • Use Room queries for raw data and Kotlin use cases for calculations.
  • Do not introduce cloud, auth, or networking.
  • Write tests for math before polishing charts.

Gemma Phase Guardrails

Do not build Gemma into the MVP core. Google’s Android LLM Inference guide says the API is optimized for high-end Android devices and does not reliably support emulators. That makes it a poor dependency for the first working version.
Allowed Gemma UseNot Allowed
Explain the weekly verdict in plain English. Change calorie targets directly.
Summarize trends from already-calculated stats. Infer missing measurements or invent data.
Draft meal ideas from your saved foods and macro targets. Use online search or hosted inference.
Answer “why did the app say hold?” using rule outputs. Override the deterministic adjustment engine.

Acceptance Criteria for MVP

  1. The app works fully offline on an Android phone.
  2. The app opens directly to Today with no onboarding.
  3. You can log calories, protein, carbs, fat, bodyweight, waist, steps, sleep, recovery scores, and training status.
  4. You can save common foods/meals and reuse them quickly.
  5. The app calculates day totals, 7-day averages, 14/28-day trends, adherence, and performance trend.
  6. The dashboard gives one calorie verdict with reason codes.
  7. Charts show weight, waist, calories, macros, adherence, and marker lifts.
  8. Targets and thresholds can be edited locally.
  9. Data can be exported and imported without a server.
  10. Core trend and adjustment logic has automated tests.
