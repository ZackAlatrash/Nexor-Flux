# Muscle-Group Icons + Active-Session Exercise Image — Design

**Date:** 2026-06-18
**Branch:** `feat/workout-tracking`
**Status:** Approved

## Goals

Two related workout-UI visual improvements:

1. **Routine preview icons** — on the Train home page, each exercise in a routine
   card currently shows an empty/broken image square. Replace it with a clean,
   consistent **muscle-group icon** derived from the exercise's target muscle,
   tinted to the theme accent. No exercise photos in this preview.
2. **Active-session exercise image** — during an active workout, the exercise row
   shows a generic dumbbell. Replace it with the **actual exercise photo**, falling
   back to the muscle-group icon when there is no image.

## Decisions

| Question | Decision |
|---|---|
| Icon visual system | Highlighted **body silhouette**, auto-cropped to the worked muscle |
| Icon source | [`react-native-body-highlighter`](https://github.com/HichamELBSI/react-native-body-highlighter) SVG path data (**MIT**), pinned commit `15df9e2dbc621450001960bed5a30e6a75357faa` |
| Icon accent | Theme accent (`LocalAppAccent`) tints the worked muscle; rest of body faint |
| Muscle-icon scope | **Train home routine cards only** (Routine Builder + exercise picker keep photos) |
| Active-session fallback | **Muscle-group icon** (not the dumbbell), shown when no image *or* image fails to load |
| Lower-body granularity | Specific highlight per muscle (quads/hamstrings/calves/glutes) when available; generic legs otherwise |

## Why this source

Research found no free icon set with a clean, *complete* per-muscle taxonomy.
The body-highlighter data is MIT, covers every group we need (front + back), is
pure bezier path data (no gradients/filters), tints cleanly to one color, and was
validated visually in the brainstorming mockup (browser-cropped to each muscle).

## Architecture

```
assets/muscles/body_front.json   { slug, d }[]   ← vendored, MIT
assets/muscles/body_back.json    { slug, d }[]

ui/train/component/MuscleArt.kt        loads+caches parsed Compose Paths per view
ui/train/component/MuscleGroup.kt      MuscleTarget + muscleTargetFor(primaryMuscles)
ui/train/component/MuscleGroupIcon.kt  @Composable Canvas icon (faint body + accent muscle)
```

Dependency flow unchanged: UI composable → MuscleArt (asset load) ; mapping is pure
Kotlin. No changes to workout-tracking/domain logic.

### Component 1 — Muscle art data (assets)

Two JSON files vendored from the pinned commit, each an array of `{ "slug": String, "d": String }`
(the `path.left` / `path.right` / `path.common` arrays flattened, tagged with the muscle slug).
Front view uses viewBox `0 0 724 1448`; back view `724 0 724 1448` (back paths are x-offset by 724).
Generated by a documented extraction script (downloads the two `.ts` from the pinned
commit and emits the JSON) so it is reproducible.

### Component 2 — `MuscleArt`

```
object MuscleArt {
    data class MusclePath(val slug: String, val path: Path)   // androidx.compose.ui.graphics.Path
    fun load(context: Context)                 // idempotent; parses + caches both views once
    fun front(): List<MusclePath>
    fun back(): List<MusclePath>
}
```

- Parses each `d` string with `androidx.compose.ui.graphics.vector.PathParser`
  (`.parsePathString(d).toPath()`) — handles the compressed arc-flag notation.
- Caches results in memory; `load()` is safe to call repeatedly.
- **Pre-warmed** in `AppContainer` init on a background dispatcher (next to the
  existing `exercises.json` asset load) so the first icon render doesn't parse on
  the main thread.

### Component 3 — `MuscleGroup` mapping (pure)

```
enum class MuscleView { FRONT, BACK }
data class MuscleTarget(val view: MuscleView, val slugs: Set<String>)

/** Maps a free-exercise-db primaryMuscles list to a highlight target, or null if unmappable. */
fun muscleTargetFor(primaryMuscles: List<String>): MuscleTarget?
```

Uses the **first** entry of `primaryMuscles`, lower-cased/trimmed. Mapping (free-exercise-db
string → target):

| primaryMuscle | view | slug(s) |
|---|---|---|
| chest | FRONT | chest |
| shoulders | FRONT | deltoids |
| abdominals | FRONT | abs, obliques |
| biceps | FRONT | biceps |
| forearms | FRONT | forearm |
| quadriceps | FRONT | quadriceps |
| triceps | BACK | triceps |
| lats | BACK | upper-back |
| middle back | BACK | upper-back |
| traps | BACK | trapezius |
| lower back | BACK | lower-back |
| glutes | BACK | gluteal |
| hamstrings | BACK | hamstring |
| calves | BACK | calves |
| adductors | FRONT | adductors |
| abductors | BACK | gluteal |
| neck | FRONT | neck |

Empty list or unknown string → `null`.

### Component 4 — `MuscleGroupIcon`

```
@Composable
fun MuscleGroupIcon(
    primaryMuscles: List<String>,
    tint: Color,
    modifier: Modifier = Modifier,
)
```

- Resolves `muscleTargetFor(primaryMuscles)`. If `null` → render the existing
  `Icons.Default.FitnessCenter` dumbbell tinted `tint` (universal fallback). Done.
- Else loads the view's `List<MusclePath>` from `MuscleArt` (remembered on `LocalContext`).
- Computes the **crop rect**: union of `getBounds()` over the target-slug paths, then
  expand to a square of side `max(w, h) * 1.55` centered on that union (mirrors the
  approved browser crop).
- Draws on a `Canvas` sized by `modifier`: map crop rect → canvas via `scale` + `translate`;
  draw every path of the view in a faint color (`Color.White.copy(alpha = 0.13f)`), then
  the target-slug paths in `tint`. Faint paths clipped to the canvas bounds.
- Faint color is a fixed low-alpha white (theme-independent, like the mockup); only the
  worked muscle takes the accent.

### Component 6 — `ExerciseCard` fallback

Add an optional parameter:

```
fun ExerciseCard(
    ...,
    fallbackMuscles: List<String>? = null,   // when image is absent/fails, show MuscleGroupIcon
    ...
)
```

Thumbnail logic becomes: if a resolved image exists, show it (via `SubcomposeAsyncImage`
so the **error/empty** state can also render the fallback); when there is no image *or* the
load fails, render `MuscleGroupIcon(fallbackMuscles, tint = accent...)` if `fallbackMuscles`
is non-null, otherwise the current `FitnessCenter` dumbbell. Existing callers that don't pass
`fallbackMuscles` (Routine Builder) keep today's behaviour exactly.

### Component 7 — Active-session image resolution (`ActiveSessionViewModel` + `ActiveSessionScreen`)

`SessionExercise` carries only `exerciseId`/`exerciseName` (no image/muscles). Resolve via the
library the VM already holds (`exerciseLibraryRepository`):

```
data class ExerciseVisual(val imagePath: String?, val primaryMuscles: List<String>)
val exerciseVisuals: StateFlow<Map<Long, ExerciseVisual>>   // keyed by exerciseId
```

Built by observing `session` and looking up each distinct `exerciseId` via
`exerciseLibraryRepository.getById(id)` (suspend) — `imagePath = exercise.images.firstOrNull()`,
`primaryMuscles = exercise.primaryMuscles`. Results cached so the same id isn't re-fetched.

In `ActiveSessionScreen.kt:251-255`, collect `exerciseVisuals` and pass:

```
val visual = visuals[se.exerciseId]
ExerciseCard(
    exerciseName = se.exerciseName,
    imageUrl = visual?.imagePath,                 // ExerciseCard resolves the CDN URL
    fallbackMuscles = visual?.primaryMuscles,     // muscle icon when no/failed image
    ...
)
```

## Data Flow

- **Routine preview:** `Exercise.primaryMuscles` → `muscleTargetFor` → `MuscleGroupIcon` (always).
- **Active session:** `exerciseId` → VM library lookup → `ExerciseVisual` → `ExerciseCard`
  → photo (Coil) with `MuscleGroupIcon` fallback on missing/failed image.

## Edge Cases

- `primaryMuscles` empty or unmapped → dumbbell fallback (via `MuscleGroupIcon` null path).
- Active-session exercise not found in library → `ExerciseVisual(null, emptyList())` → dumbbell.
- Offline / image load failure → `SubcomposeAsyncImage` error slot → muscle icon.
- `MuscleArt` asset missing/corrupt → `load()` degrades to empty lists; `MuscleGroupIcon`
  then renders the dumbbell fallback (never crashes).

## Testing

- **Unit (pure):** `muscleTargetFor` — every free-exercise-db muscle string maps to the
  expected `MuscleTarget`; unknown string and empty list → `null`; first-of-list precedence.
- **Manual (user, in-app):** routine cards show correct, legible muscle icons in theme accent;
  active session shows real photos with muscle-icon fallback. Build + type-check before handoff.

## Out of Scope

- Routine Builder and exercise-picker icons (kept as photos).
- Any change to workout-tracking/set/session logic.
- A full in-app licenses screen (single `THIRD_PARTY_NOTICES.md` entry suffices).
- Female body variants (male front/back only).
